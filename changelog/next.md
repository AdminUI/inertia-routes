- **Improvement**: A per-call `onSuccess` now runs alongside the `visitOptions.onSuccess` set in the composable options instead of replacing it (user's first, then the per-call one)
- **Fix**: `form.get/post/put/patch/delete/submit` no longer throw when called without options (e.g. `form.post()` or `form.post(url)`) while `resetOnSuccess` is enabled
- **Fix**: Per-call visit options (`preserveScroll`, `onError`, `headers`, etc.) no longer leak into later submits
- **Fix**: `resetOnSuccess` no longer stacks an extra `onSuccess` wrapper on every submit, which caused repeated resets and repeated callbacks
- **Fix**: Options objects passed by the caller are no longer mutated
- **Fix**: `onSuccess` callbacks now receive the `page` and are awaited, and they run before `resetOnSuccess` clears the form so they can still read the submitted data
- **Fix**: `resetOnSuccess` no longer resets to a snapshot that shares nested arrays and objects with the live form
- **Fix**: `resetOnSuccess` now falls back to the form's own defaults when no hydrated snapshot exists (`data` as a function, `autoHydrate: false`, or a submit before the meta request returns)
- **Fix**: Array field defaults no longer pick the wrong type when another field's name starts with the same prefix (e.g. `items` and `items_count`)
